## 验证步骤

### 第1步：启动全栈（同 G-3.4）

### 第2步：逐动作验证

每个动作按照「API 调用 → 检查 DB → 检查前端 UI」三步验证。

#### 动作 1：禁用用户

```
1. 浏览器打开 http://localhost:5174 → 登录 admin
2. 导航到"用户管理"视图
3. 对一个 visitor 用户点击"禁用"
4. 【验证】该用户无法再登录（用其 token 访问 /auth/me 应返回 401）
5. 重新启用该用户
6. 【验证】该用户可以正常登录
```

#### 动作 2：增删改角色卡

```
1. 管理端创建新角色卡（填写 name/description/personality）
2. 【验证】API 返回 201，DB personas 表有新记录
3. 修改角色卡 description
4. 【验证】API 返回 200，DB 记录已更新
5. 删除角色卡
6. 【验证】API 返回 200，DB 记录 deleted_at 非空（软删除）
```

#### 动作 3：上传/重处理文档

```
1. 上传一个 .txt 文件
2. 【验证】API 返回 201，status=pending → polling → status=ready
3. 点击"重新向量化"
4. 【验证】文档重新处理后 status=ready，chunk_count > 0
```

#### 动作 4：上传/删除资源

```
1. 上传背景图（JPEG < 5MB）
2. 【验证】OSS 中有该文件，列表中出现
3. 删除该背景
4. 【验证】列表不再出现，OSS 中已删除
```

#### 动作 5：修改系统设置

```
1. 修改 LLM model 为 deepseek-chat
2. 【验证】API 返回 200，GET settings 确认修改
3. 确认 API key 在 GET 响应中被脱敏（显示为 ***）
```

#### 动作 6：查询审计日志

```
1. 执行以上任意管理操作
2. 打开"审计日志"视图
3. 【验证】刚才的操作出现在审计日志中
4. 按 path 过滤 → 正确过滤
5. CSV 导出 → 下载文件包含正确数据
```
